# 항체 설계·평가 매뉴얼

`ppt.pptx`의 스크린샷 20장을 그대로 써서 만든 웹 매뉴얼입니다. 한국어/중국어 전환됩니다.

## 파일

| 파일 | 설명 |
|---|---|
| `index.html` | 매뉴얼 본체. 단일 파일, 외부 의존성 없음 |
| `images/` | 빨간 박스 주석이 들어간 스크린샷 26장 |
| `src/` | 주석 전 원본 스크린샷 |
| `annotate.py` | `src/`의 원본에 빨간 박스를 입혀 `images/`를 만드는 스크립트 |
| `ppt.pptx` | 원본 |

## 구성

| 단계 | 내용 | 사용 이미지 |
|---|---|---|
| STEP 0 | 전체 흐름, Lab 화면, Ctrl+K 검색 | 01, 02 |
| STEP 1 | RFantibody — 프레임워크 / 구조 입력 / 파라미터 / 작업 확인 | 03, 04, 05, 06 |
| STEP 2 | 신뢰도 — ipSAE·pLDDT·RMSD, CDR별 pLDDT, 지표 상세 나머지 탭, 서열 꺼내기 | 07, 08, 08b, 09 |
| STEP 3 | TAP 개발성 — 입력 2단계 + best 파일 선택 + 판정표 + 그래프 5장 | 10, 11, 11b, 12, 13, 13a~13e |
| STEP 4 | ImmuScope 면역원성 — 서열/allele 입력 + 히트맵 3장 | 14, 15, 16, 17, 18, 19 |
| STEP 5 | 비교표, 제출물, 자주 발생하는 오류 | — |

TiDE-Ab는 뺐습니다. 백본만 만들고 서열을 설계하지 않아 뒤에 AbMPNN과 구조 예측을 또 붙여야 하므로, 한 번에 끝나는 RFantibody 한 갈래로 정리했습니다.

## 빨간 박스 수정하기

`annotate.py`의 `JOBS`에서 좌표를 고치고 다시 실행합니다. 좌표는 `(x0, y0, x1, y1)` **비율**(0~1)이라 해상도와 무관합니다.

```python
"04-rfab-target": ("s04_1.png", [
    (.199,.215,.551,.263),   # ① 타겟 구조
    (.197,.352,.232,.384),   # ② 항원 체인
    ...
```

```bash
python annotate.py
```

번호 배지는 박스 바깥 왼쪽에 자동으로 붙고, 왼쪽 공간이 없으면 위쪽으로 갑니다.
`index.html`의 설명 순서(`items` 배열)가 박스 번호와 1:1로 대응하므로, 박스를 추가하면 설명도 같은 순서로 추가해야 합니다.

## 글 고치기

모든 문구는 `index.html` 안 `T` 객체에 `{ko: '...', zh: '...'}` 쌍으로만 있습니다. 여기만 고치면 양쪽 언어에 반영됩니다.

## 추가로 필요한 캡처

지금 매뉴얼에서 글로만 설명하고 있는 화면입니다. 채팅에 이미지를 붙여 주시면 그대로 넣습니다.

| 우선 | 화면 | 쓰이는 곳 |
|---|---|---|
| 낮음 | `지표 상세` → **② 상대 배치** 탭 | STEP 2. 참고 지표라 없어도 됩니다 |
| 낮음 | `지표 상세` → **④ 접촉** 탭 | STEP 2. 수치(접촉 수 13, f CDR 0.857 등)는 글로 적어 뒀습니다 |
| 낮음 | 결과 `Download All` 또는 파일 탭 | STEP 5 제출물 준비 |

받은 캡처는 모두 반영했습니다.

- **TAP 결과 수치표** → `images/13-tap-metrics.png`. Value / Flag / Threshold / 보기 전환 네 군데에 박스. STEP 3에서 그래프보다 앞에 둡니다. 예시의 PSH 202.62(RED)가 판정 사례가 됩니다.
- **지표 상세 ③ 국소 interface** → `images/08b-metric-detail-tabs.png`. 네 개 탭이 참고 지표라는 점만 짧게 설명합니다.
- **결과 파일 선택기** → `images/11b-file-picker-best.png`. 아래 "best 구조" 항목 참조.
- **ImmuScope 결과 표** → 넣지 않았습니다. 원본 TSV가 2,000행이 넘어 표로는 판단할 수 없으므로 히트맵으로만 보도록 STEP 4에 안내를 넣었습니다.

## 반영한 내용 두 가지

**1. clash는 다루지 않습니다.** `지표 상세`의 네 탭 어디에도 clash 수치가 없는 것을 확인했습니다. 매뉴얼에서 clash 판정을 빼고, 나머지 세 탭(`상대 배치` / `국소 interface` / `접촉`)은 "후보를 좁힌 뒤 근거로 쓰는 참고 지표" 정도로만 설명합니다. 물리적 타당성은 3D에서 계면을 확대해 보라고만 적었습니다.

**2. best 구조가 최종 결과물입니다.** `_best.pdb`가 마지막 refolding 검증까지 끝난 구조라는 점을 두 군데에 넣었습니다.

- STEP 2 끝 — 구조를 꺼낼 때 항상 이 파일을 기준으로 할 것
- STEP 3 파일 선택 — 11개 파일 중 왜 이것만 쓰는지. `_traj`는 중간 기록, `target_*`·`framework_*`는 입력, `_dldesign_0.pdb`는 검증 전 단계라고 구분해 뒀습니다
